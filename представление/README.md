PDF — формат документа с фиксированным расположением текста и изображений. Документ самодостаточен: контекст, роль, процесс, модель учёта, разбор решения и результаты проверки. Ссылки ведут к подробным материалам.

## Исходник и пересборка

Текст находится в функции `pages`, оформление схем — в функции `diagrams` программы [собрать.py](собрать.py). Из одного описания создаются PDF, краткий текст и изображения. Показатели читаются из [вымышленного примера](../примеры/02-данные.json), а не вводятся в PDF вручную.

Для сборки нужны Python 3.10 или новее, зависимости из [requirements.txt](requirements.txt) и установленные в системе шрифты DejaVu Sans. Файлы шрифтов в репозиторий не включены. На Linux стандартная папка — `/usr/share/fonts/truetype/dejavu`; для другой системы задайте переменную окружения `CASE_FONT_DIR` с путём к установленным `DejaVuSans.ttf` и `DejaVuSans-Bold.ttf`.

Из корня репозитория:

```bash
python -m pip install -r представление/requirements.txt
python представление/собрать.py
python проверки/проверить.py
python проверки/проверить-представление.py
```

Программа перезаписывает только результаты представления: PDF, `кейс.md`, две схемы и `проверка-сборки.json`. Исходный пример и рабочие документы не изменяются.

## Контроль актуальности

[Проверка сборки](проверка-сборки.json) содержит показатели и контрольные суммы файлов. Контрольная сумма позволяет обнаружить изменение файла. Не редактируйте созданный PDF или краткий текст отдельно от исходника: после правок выполните сборку и проверки, затем сохраните обновлённые файлы вместе.

В GitHub проверяются исходный кейс и представление. Ветка `portfolio-presentation` также используется для публикации пересобранных файлов; в `main` автоматическая запись отключена. Проверка целостности не заменяет визуальный просмотр страниц после изменения оформления.
