# Разборы рабочих ситуаций

[К содержанию](../README.md) · [Данные волны](02-данные.json) · [Сводка](03-сводка.md)

Все номера, приложения и события вымышлены. Они показывают применение правил, а не фактические обращения банка.

## 1. Удалённая установка завершилась успешно

**АРМ:** `DEMO-ARM-001`. Автоматизация предоставила подтверждение установки только Astra, событие `DEMO-EVT-001`.

Аналитик связывает результат с задачей установки, фиксирует конфигурацию и проверяет наличие открытых обращений. Задача установки завершается. Дополнительная приёмка пользователя не объявляется новым условием миграции: исходный критерий — установленная Astra.

**В сводке:** один АРМ с установленной Astra и один АРМ без Windows.

## 2. Нужен инженер, но работа сотрудника не нарушена

**АРМ:** `DEMO-ARM-005`. Автоматизация зафиксировала неуспешную удалённую попытку и необходимость разрешённых ручных работ. Текущая Windows работоспособна.

Аналитик проверяет причину передачи и связь с попыткой. Вопрос организации ручных работ проходит через начальника и куратора. Инженер получает конкретное задание с допустимыми действиями, а не просьбу повторно выяснить всю историю.

**В сводке:** Astra ещё не установлена; есть ручная работа. Инцидент не создаётся автоматически только из-за неудачной установки.

## 3. Ручной способ не решит ограничение оборудования

**АРМ:** `DEMO-ARM-006`. Профильная группа передала сведения об ограничении оборудования; необходимое решение ещё не принято.

Аналитик фиксирует ожидание профильного решения и контрольный срок. Не требует от инженера «поставить любым способом» и не признаёт оборудование совместимым сам. Влияние на план передаётся начальнику.

**В сводке:** Windows; ожидание решения. Это не готовая к немедленному выполнению ручная установка.

## 4. Два приложения удерживают Windows

**АРМ:** `DEMO-ARM-004`. Astra установлена в режиме двойной загрузки. Для Приложения А получено применимое решение, для Приложения Б готовность не подтверждена.

Задача установки завершена. Задача `DEMO-WIN-004` остаётся в ожидании готовности ПО. Аналитик связывает первое решение, сохраняет вторую зависимость и запрашивает её состояние у сопровождения ПО.

**В сводке:** Astra установлена; Windows остаётся. Готовность одной зависимости не позволяет скрыть вторую.

## 5. Команда получена, но работы ещё не выполнены

**АРМ:** `DEMO-ARM-009`. Сопровождение ПО выдало команду `DEMO-CMD-009`, применимую к этому АРМ и его единственной зависимости. Вывод Windows запланирован, результат ещё не получен.

Аналитик контролирует назначенную работу и согласованное время, а не закрывает задачу по факту команды.

**В сводке:** по-прежнему двойная загрузка. В перечне обязательств — запланированный вывод Windows.

## 6. Установка завершена, функция не работает

**АРМ:** `DEMO-ARM-008`. Установка только Astra подтверждена, но есть обращение `DEMO-INC-008` о недоступной рабочей функции. Причина устанавливается профильной группой.

Аналитик контролирует инцидент, назначение и следующий результат. Не снимает подтверждённую установку из учёта и не закрывает обращение вслед за задачей миграции.

**В сводке:** АРМ входит в число установленных Astra; отдельно показаны один открытый инцидент и одно затронутое АРМ. Причинность миграции не объявляется установленной без диагностики.

## 7. Пришло задание, но нет результата

**АРМ:** `DEMO-ARM-007`. По текущей попытке нет достаточного подтверждения конфигурации.

Аналитик запрашивает у автоматизации состояние задания и назначает контроль следующего ответа по согласованному порядку. Не отмечает установку успешной и не организует повторную операцию, исходя лишь из отсутствия ответа.

**В сводке:** «Не подтверждено». Это не равно Windows и не равно установленной Astra.

## 8. Восстановление потребовало возврата к Windows

**АРМ:** `DEMO-ARM-012`. Сначала событием `DEMO-EVT-012` подтверждена установка Astra. Затем по разрешённому решению выполнено восстановление конфигурации Windows, событие `DEMO-EVT-013`. Инцидент завершён по установленному процессу; повторные работы ещё планируются.

Аналитик сохраняет оба события, меняет текущее состояние и связывает новую работу. История первоначальной установки остаётся доступной.

**В сводке:** исторически Astra устанавливалась на восьми АРМ, но сейчас установлена на семи. Двенадцатое АРМ относится к Windows, а восстановление сервиса не подменяет полный переход.

## Пример запроса начальнику

> По демонстрационной волне остаются ручные установки `DEMO-ARM-005` и `DEMO-ARM-010`. Для первой требуется завершить назначение работ на площадке, для второй — согласовать время доступа. Прошу определить порядок организации через кураторов. Отдельно по `DEMO-ARM-006` требуется решение профильного подразделения об оборудовании; назначение ещё одного инженера само по себе это препятствие не снимает.

Конкретные даты, срочность и доступные ресурсы в реальной работе берутся из плана и ответов участников, а не из этого вымышленного примера.
