## Что требует следующего действия

| Запись | Состояние | Следующий шаг |
|---|---|---|
| `DEMO-ARM-005` | Нужны ручные работы после неуспешной удалённой попытки | Организовать работы через начальника и куратора |
| `DEMO-ARM-006` | Ограничение оборудования | Получить профильное решение; не подменять его повторной установкой |
| `DEMO-ARM-007` | Нет подтверждённого результата | Автоматизации уточнить текущую попытку и конфигурацию |
| `DEMO-ARM-010` | Нужны ручные работы | Согласовать время доступа по правилам площадки |
| `DEMO-ARM-012` | После восстановления снова Windows | Определить маршрут связанных повторных работ |
| `DEMO-WIN-003` | Ожидается готовность приложения | Получить прогноз у сопровождения ПО |
| `DEMO-WIN-004` | Снята только одна из двух зависимостей | Получить решение по Приложению Б |
| `DEMO-WIN-009` | Команда получена, вывод Windows запланирован | Проконтролировать выполнение и результат |
| `DEMO-INC-008` | Инцидент открыт при установленной Astra | Получить профильную диагностику и контролировать восстановление |

## Вопросы начальнику

По ручным работам для `DEMO-ARM-005` и `DEMO-ARM-010` требуется обеспечить локальную организацию через кураторов. По `DEMO-ARM-006` необходимо проконтролировать получение профильного решения об оборудовании; выделение дополнительного инженера не снимает техническое ограничение автоматически.

Сведения о фактической доступности ресурсов и сроках восстановления в примере не заданы. Поэтому сводка не объявляет просрочку SLA и не предлагает выдуманные сроки её устранения.

## Ограничения интерпретации

Состав волны в примере не менялся. Открытый инцидент не вычитается из семи подтверждённых установок. Двойная загрузка входит в факт установки Astra, но не в четыре АРМ без Windows.

Исторические восемь установок не подменяют текущие семь: `DEMO-ARM-012` после установки возвращено к Windows. Успешное восстановление его работы не завершает повторную миграцию.
