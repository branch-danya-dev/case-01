# 10. Проверка правил и примеров

[К содержанию](../README.md) · [Далее: представление кейса](11-представление-кейса.md)

## Объект проверки

Проверяются логика описания, связи записей и расчёт сводки. Не проверяются установка Astra Linux, совместимость банковского ПО и фактическая настройка Service Desk. Это не технический пилот и не расширение ответственности аналитика.

**Отрицательная проверка** — намеренное внесение ошибки в копию примера, чтобы убедиться, что правило её обнаруживает. Исходный набор данных при этом не изменяется.

## Сценарии

| Код | Условия | Ожидаемый результат |
|---|---|---|
| ПР-01 | Один АРМ дважды внесён в одну волну | Дубль обнаружен; в корректном учёте один АРМ не считается дважды |
| ПР-02 | Для АРМ повторно пришёл результат одной попытки | История не создаёт дополнительное участие или дополнительный мигрированный АРМ |
| ПР-03 | Установка Astra подтверждена, инцидент открыт | Установка учитывается, инцидент остаётся отдельным обязательством |
| ПР-04 | Задание отправлено, результата нет | Успешная установка не засчитывается; при отсутствии иных сведений конфигурация неподтверждённая |
| ПР-05 | Удалённая попытка неуспешна, нужна ручная установка | Сохраняются результат попытки, основание передачи и связанная работа инженера |
| ПР-06 | Установлена двойная загрузка | Установка завершена, существует незавершённая задача вывода Windows |
| ПР-07 | Из двух зависимостей одна не готова | Вывод Windows не признаётся готовым к выполнению |
| ПР-08 | Инцидент передан другой группе | Передача не считается восстановлением; виден следующий исполнитель |
| ПР-09 | Один общий инцидент затронул несколько АРМ | Считаются один инцидент и отдельное число уникальных затронутых АРМ |
| ПР-10 | Задача находится в ожидании | Есть причина, ответственный за следующее действие и дата контроля |
| ПР-11 | Получена команда, но Windows ещё не выведена | Задача может быть запланирована; конфигурация остаётся двойной |
| ПР-12 | Команда не относится к АРМ или не покрывает известную зависимость | Требуется уточнение у сопровождения ПО; выполнение не выводится из предположения аналитика |
| ПР-13 | АРМ перенесено из состава волны | Есть решение и новая версия состава; предыдущая сводка не меняется скрытно |
| ПР-14 | Astra была установлена, затем восстановлена только Windows | Историческая установка сохраняется; текущая сводка относит АРМ к Windows, видны повторные работы |
| ПР-15 | Есть четыре категории конфигурации | Их сумма равна объёму версии волны; при нулевом объёме процент не применяется |
| ПР-16 | Для восстановления выбран разрешённый временный способ | Инцидент может быть завершён по действующим правилам, но обязательство полного перехода сохраняется |
| ПР-17 | Набор содержит противоречивые или неподтверждённые сведения | Неопределённость показана отдельно; источники не подменяются догадкой |
| ПР-18 | Нужно перераспределить инженеров или раскрыть сведения закрытой площадки | Решение принимается уполномоченным участником; аналитик не действует в обход полномочий |

## Что выполняет локальная программа

[Программа проверки](../проверки/проверить.py) работает только с вымышленным [набором данных](../примеры/02-данные.json). Она проверяет ссылки между файлами, идентификаторы, допустимые состояния, подтверждения установки, обязательства при двойной загрузке и расчёт сводки. Затем запускает положительные и отрицательные проверки на копиях набора.

Смысл применимости команды в примере задаётся явно. Программа может проверить наличие отметки и связи, но не подтвердить реальную совместимость приложения или полномочия автора банковского решения.

Она также не проверяет маршрутизацию действующего Service Desk, сроки SLA/OLA и права доступа. Эти части проверяются уполномоченными владельцами в своей среде, а не данным сценарием Python.

## Порядок запуска

Из корневой папки репозитория:

```bash
python проверки/проверить.py
```

Требуется Python версии 3.10 или новее; сторонние библиотеки и подключение к сети не нужны. Программа читает файлы и выводит результат. Никакие операционные системы не устанавливаются и не удаляются.

Для демонстрационного среза ожидаются 12 АРМ, 7 с установленной Astra сейчас, 4 только с Astra, 3 с двойной загрузкой, 4 с Windows и 1 с неподтверждённым состоянием. Исторически установка подтверждена на 8 АРМ. Открыт один инцидент, затронуто одно АРМ.

## Критерий готовности самого кейса

Связи документов не ведут в отсутствующие файлы. Примеры соответствуют установленным правилам. Показатели воспроизводимы. Противоречивые примеры отклоняются. Предлагаемые организационные решения не выдаются за уже утверждённые настройки или достигнутые результаты банка.
