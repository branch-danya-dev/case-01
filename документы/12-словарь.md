# 12. Словарь терминов

[К содержанию](../README.md)

| Термин | Объяснение |
|---|---|
| АРМ | Автоматизированное рабочее место. Единица учёта, на которой выполняются работы миграции. Может быть физическим компьютером либо согласованным удалённым рабочим местом |
| ОС | Операционная система. Основное программное обеспечение, обеспечивающее работу компьютера и запуск приложений |
| ПО | Программное обеспечение: приложения и другие программы |
| Astra Linux | Наименование целевой операционной системы в условиях кейса. Конкретная версия и конфигурация не задаются |
| Windows | Наименование исходной операционной системы в условиях кейса |
| Миграция | Переход с одной технологической среды на другую. В данном кейсе формальный результат для АРМ — подтверждённая установка Astra |
| Волна миграции | Набор АРМ, запланированных к переходу в определённый период |
| Гибридная среда | Одновременное существование разных технологических сред, здесь — Windows и Astra |
| Dualboot, двойная загрузка | Две ОС на одном компьютере с выбором при запуске. В кейсе — Astra и Windows |
| Конфигурация | Подтверждённое фактическое состояние рабочего места, например наличие одной или двух ОС |
| Удалённое АРМ | Рабочее место, к которому пользователь подключается с другого устройства. Его нельзя автоматически отождествлять с устройством подключения |
| Ферма удалённых АРМ | Совокупность ресурсов, предоставляющих удалённые рабочие места. Техническое устройство фермы в кейсе не раскрывается |
| Service Desk | Принятое название службы и средств обработки обращений. Здесь условно обозначает существующую систему регистрации задач и инцидентов |
| ITSM — Information Technology Service Management | Управление ИТ-услугами. **ИТ — информационные технологии**. Не название конкретной программы |
| SLA — Service Level Agreement | Соглашение об уровне обслуживания, включая принятые обязательства по срокам и качеству сервиса |
| OLA — Operational Level Agreement | Соглашение о взаимодействии внутренних подразделений при оказании сервиса |
| Инцидент | Нарушение или ухудшение нормальной работы сервиса |
| Проблема | Причина или возможная причина одного либо нескольких инцидентов, исследуемая профильными участниками |
| Задача | Запись о необходимой работе: что выполнить, кто отвечает и какой результат получить |
| Зависимость | Условие, без выполнения которого нельзя завершить другое действие. Например, готовность приложения перед выводом Windows |
| Препятствие | Причина, по которой работа сейчас не может продолжиться |
| Эскалация | Передача вопроса участнику с нужными полномочиями или компетенцией |
| Контрольный срок | Момент, к которому нужно получить результат либо повторно уточнить состояние. Не обязательно срок восстановления по SLA |
| Куратор | Ответственный за организацию работы сотрудников сопровождения на своей площадке в пределах полномочий |
| VIP — Very Important Person | Обозначение особо обслуживаемой категории пользователей. Само по себе не определяет максимальный приоритет любого инцидента |
| Профильная группа | Подразделение, отвечающее за соответствующее направление: оборудование, автоматизацию, приложение и другое |
| Третья линия сопровождения | Уровень профильных специалистов, которым передаются сложные вопросы. В исходных условиях к нему относится группа автоматизации |
| Карточка | Запись об АРМ, задаче, инциденте или другом объекте в системе учёта |
| Идентификатор | Однозначное обозначение записи. В примерах префикс DEMO указывает на вымышленный демонстрационный номер |
| Состояние | Текущее положение объекта или работы. Состояние установки и конфигурация ОС — разные сведения |
| История изменений | Сохранённая последовательность событий: кто, когда и на каком основании изменил запись |
| Срез отчёта | Представление данных на определённый момент времени |
| Логическая модель | Описание объектов, сведений и связей между ними без привязки к физическому устройству базы данных |
| Требование | Проверяемое описание нужного правила или возможности |
| Функциональное требование | Описание того, что процесс или система должны делать |
| Требование к качеству | Ограничение по доступу, сохранности истории, производительности или другим свойствам работы |
| Условие проверки | Признак, по которому можно установить выполнение требования |
| BPMN — Business Process Model and Notation | Стандарт графического описания деловых процессов. Схемы в этом репозитории упрощённые и не выдаются за формальные BPMN-модели |
| GitHub | Платформа, на которой размещены файлы этого кейса |
| Репозиторий | Хранилище файлов проекта с историей изменений |
| README | Принятое имя начального файла с описанием проекта и навигацией |
| Markdown | Текстовый формат оформления заголовков, таблиц, ссылок и других элементов документов. Используется в файлах с расширением .md |
| Mermaid | Средство описания диаграмм текстом. В документах используются блоки mermaid, которые GitHub отображает как схемы |
| JSON — JavaScript Object Notation | Текстовый формат структурированных данных. В нём записан вымышленный пример волны |
| Python | Язык программирования, на котором написана локальная проверка примеров |
| UTC — Coordinated Universal Time | Всемирное координированное время. Обозначение +03:00 в примере означает смещение на три часа относительно UTC |
